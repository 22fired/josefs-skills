# Token Efficiency

Correctness and evidence come before brevity. Project instructions and an active output style take precedence.

- Locate before reading: search symbols or content, then read only the relevant ranges. Read wider when correctness requires it.
- Filter noisy commands at the source. Keep decisive errors, failures, numbers, paths, and code verbatim; widen the filter if the cause is unclear.
- Do not repeat reads or commands without new information or changed state.
- Answer first. Omit preamble, restatement, and process narration.
- If the cheap approach fails twice, escalate instead of repeating it.
